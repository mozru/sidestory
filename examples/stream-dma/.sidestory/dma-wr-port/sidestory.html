Where backpressure enters the engine: when the write bus isn't ready, neither is the packer, and the FIFO starts to fill.

Inside dma_wr_port

Data and strobes pass straight through from the packer; the logic is the request register, the beat counter, and the wait for the response. Click a block to see its code.

Valid and ready, passed through

pk_ready = wr_dat_ready && sending: the bus's ready is the packer's ready. A stall on the bus stops the packer the same cycle; the packer stops popping, and the FIFO fills until almost_full holds off the next read.

Request, beats, response

start loads address and length; the request stays valid until taken. wr_dat_last marks the burst's final beat (left_q == 1); after it, rsp_q waits for wr_rsp_valid.

busy lets writes overlap reads

busy covers request, data and response. dma_ctrl starts a write and goes back to reading; it only waits (WAIT_WRITE) when it wants to start another write while this one is still busy.
