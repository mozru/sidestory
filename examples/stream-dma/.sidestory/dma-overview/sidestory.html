A memory-to-memory DMA engine in eight SystemVerilog modules: it reads a source buffer in bursts, realigns the bytes to the destination's alignment, and writes them out, while a small FSM decides what happens when. Read this page for the shape of the system; dive into a block only when you need it.

The engine at a glance

Two planes. Along the bottom, the data path carries 64-bit beats left to right: read bus → dma_rd_port → dma_fifo → dma_packer → dma_wr_port → write bus. Along the top, the control path: the CPU programs dma_csr, which starts dma_ctrl; the FSM tells two dma_addr_gens and the ports what to do, one strobe at a time.

One transfer, start to finish

  1. Program. Software writes SRC, DST and LEN, then CTRL.start. dma_csr turns the write into a one-cycle start pulse.
  2. Load. In LOAD, dma_ctrl strobes load: both address generators latch their base and count the beats the transfer touches; the packer latches the lane offsets; the FIFO empties.
  3. Read. READ_BURST pulses rd_start: the read port requests a burst (at most 16 beats, never across 4 KB) and pushes the response beats into the FIFO.
  4. Realign. The packer pops beats as the write side takes them, rotating bytes by dst_off − src_off lanes.
  5. Write. Once enough beats arrived (the credit check), WRITE_BURST pulses wr_start; that write runs in the background while the FSM goes back to reading.
  6. Finish. With nothing left to write and the port idle, DONE sets STATUS.done and irq rises.
The rule that keeps it simple: only dma_ctrl decides; every other block either moves data or counts it. Decisions travel as one-cycle strobes (load, rd_start, wr_start), facts come back as levels and pulses (has_burst, almost_full, rd_done).

Watch it run

A cycle-accurate model of the RTL copies 400 bytes from 0x0fa5 to 0x2002. Play or step it: the FSM's current case item lights up in the editor, beats travel along the data wires, control wires light while their signal is active, and the FIFO fills. Pick a bus scenario to see backpressure and errors.

Without the simulation: one transfer of 400 bytes takes about 140 cycles. The FSM alternates READ_BURST → WAIT_DATA (a read burst arrives in the FIFO) and WRITE_BURST (a write burst starts and runs in the background). The first read burst is only 12 beats because the source reaches a 4 KB boundary; after the second, the FIFO is almost full (more than 16 beats), so READ_BURST skips straight to writing.

Control path: CSR → FSM → strobes

dma_csr holds the configuration and makes start. dma_ctrl is the only block with a state machine; it never touches data. Its outputs are strobes, one cycle wide, each owned by one state:

The same rd_start wire is both the port's "go" and the address generator's "taken", so the two can't disagree about which burst is current.

Data path: read → FIFO → packer → write

Every 64-bit beat takes the same route, and nothing on it waits for the FSM: each hop is a valid/ready handshake.

The packer is where alignment happens: a byte in source lane i leaves in lane (i + dst_off − src_off) mod 8, so one output beat is cut from two input beats.

Backpressure: almost_full

When the write bus stalls (wr_dat_ready low), the packer stops popping, the FIFO fills, and its almost_full flag (more than 16 of 32 beats: no room for another full burst) tells READ_BURST not to issue a read. No read is ever requested that the FIFO can't hold, so rd_rsp_ready rarely has to drop on the bus.

Backpressure in focus: wr_dat_ready → pk_ready → fifo_pop, and fifo_almost_full back to dma_ctrl.

Errors and the interrupt

A read response with an error ends that burst in WAIT_DATA; a failed write response can arrive in any state (writes overlap reads), so it overrides the next state. Either way the FSM sits in ERROR and raises drain: the packer empties the FIFO and feeds any open write burst with empty-strobe beats, so the bus sees complete bursts. When both ports are idle, err_set records the code in ERR (1 zero length, 2 read, 3 write).

STATUS.done and STATUS.error are set here and cleared by a new start or a write of 1. irq is simply irq_en && (done || error).
