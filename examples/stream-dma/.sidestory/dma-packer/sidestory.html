The source and destination can start at any byte. The packer moves every byte from its source lane to its destination lane, one 64-bit beat at a time, and marks the bytes that are real with strobes.

Inside dma_packer

The datapath is a register and a barrel shifter. The control decides when a beat comes in, when one goes out, and which bytes of it count. Click a block to see its code.

Two beats in, one beat out

A byte in source lane i belongs in destination lane (i + shift) mod 8, with shift = dst_off − src_off. Lanes that wrap past 7 belong to the next output beat, so each output beat is cut from a 16-byte window of the current and the previous input beat:

out_data = {in_data, prev_q} >> (8 − shift) × 8

27 bytes from offset 5 to offset 2 (shift = 5 lanes, with a prime). Input beat 0 holds bytes 0–2 in lanes 5–7; output beat 0 needs bytes 0–5 in lanes 2–7, so it takes bytes 0–2 from input beat 0 (the previous beat) and 3–5 from input beat 1:

lane76543210 in 0210····· in 1109876543 out 0543210··

Prime and flush

casewhenwhat the packer does
primedst_off < src_offOutput beat 0 needs input beat 1, so take input beat 0 into prev_q without emitting (in_ready without out_valid).
steadyotherwiseOne in, one out, in the same cycle: in_ready follows out_ready.
flushin_left_q == 0The last output beat may need only bytes already in prev_q: emit it with zeros on top, consuming nothing.

That's why dma_ctrl's credit check adds one beat when it primes, and why input and output beat counts can differ by one.

Strobes: which bytes are real

The first output beat starts at dst_off; the last ends at (dst_off + len − 1) mod 8. Both masks are computed once, at load; a one-beat transfer gets both. While draining after an error, every strobe is 0, so the beats that finish an open write burst write nothing.
