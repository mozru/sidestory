The only block in the engine that decides anything. It moves no data: it reads facts from the datapath (bursts left, beats arrived, FIFO almost full, done, error) and answers with one-cycle strobes.

The state graph, read from the code

Eight states. The loop in the middle is the engine's heartbeat: READ_BURST → WAIT_DATA → WRITE_BURST → READ_BURST, with a write running in the background while the next read goes out. Hover a transition to highlight the line that takes it; click a state to highlight its case item.

The same graph, drawn when the code was written: IDLE → LOAD on start; LOAD → READ_BURST (or ERROR on a zero length); READ_BURST → WAIT_DATA after issuing a read, or → WRITE_BURST when nothing is left to read or the FIFO is almost full; WAIT_DATA → WRITE_BURST with credit, else back to READ_BURST; WRITE_BURST starts a write and returns to READ_BURST, waits in WAIT_WRITE while the port is busy, or finishes in DONE.

The credit check

A write burst must never wait for data that hasn't been requested: the write port would hold the bus while the FSM, waiting for it, never issues the read that would feed it. So a write of wr_burst_len beats starts only when the beats already in hand cover it:

in_rcvd_q ≥ out_issued_q + wr_burst_len + extra_q

extra_q is the packer's priming beat: when the destination's lane offset is smaller than the source's, the first output beat needs bytes from the second input beat, so every output beat runs one input beat behind. Once every read is in (!rd_has_burst) credit is unconditional.

Write errors can come at any time

Because a write burst runs while the FSM is already reading, its response can arrive in READ_BURST or WAIT_DATA. Rather than repeat the check in every state, the end of the always_comb overrides whatever the case statement chose: cancel this cycle's strobes, record error code 3, go to ERROR. In ERROR, drain stays high until both ports are idle, so no burst is left half-done on the bus.

Registers

The state register, the error code, and the two counters behind the credit check. load clears the counters and latches extra_q; after that, in_rcvd_q counts every FIFO push and out_issued_q adds each write burst's length as it is issued (not as it completes: credit is about promises).
