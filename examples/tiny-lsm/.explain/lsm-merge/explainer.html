An LSM tree keeps the same key in several places at once: a new value in the memtable, older ones in tables below. Scans and compactions both need one stream out of all of them: every key once, in order, with its newest entry. merge.py does that in fifteen lines with a heap.

k sorted sources, one sorted stream

Each source is already sorted, so the next key overall is the smallest of the sources' next keys. A heap holds at most one entry per source and finds that smallest in O(log k); merging n entries costs O(n log k), and the heap itself holds only one entry per source (a table source keeps one block in memory, and the memtable source is its snapshot).

The order is (key, rank), where rank is the source's position, 0 for the newest. For a key held by several sources, the newest one's entry pops first.

The loop, step by step

A scan of everything, over three sources: the memtable (rank 0), an L0 table and an L1 table. Each step pops the smallest entry, refills from its source, and pops (and refills past) any older entries for the same key.

Green: each source's next entry, the one on the heap. Filled: the entry popped this step. Red dashed: an older entry for the same key, skipped.

_push_next: one entry per source

After a pop, the source that lost its entry gives the heap its next one, if it has any. Because no source holds a key twice, a source's next key is always larger than the one just popped, so the heap order stays correct. The tuple's first two fields, key and rank, are unique, so Python never has to compare values or iterators.
